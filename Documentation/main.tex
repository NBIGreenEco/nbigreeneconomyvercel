\section{Executive Summary}
The Green Economy Toolkit is a comprehensive digital platform developed for the National Business Initiative (NBI) to accelerate green economy adoption across South Africa. The platform provides multilingual access (English, isiZulu, Setswana), AI-powered search, funding opportunities aggregation, and an embedded digital avatar for interactive user engagement. The toolkit serves entrepreneurs, SMME businesses, TVET colleges, and communities seeking green economy resources and opportunities.

% Key Achievements:
\begin{itemize}
    \item \textbf{Fully deployed platform} at \texttt{greeneconomytoolkit.com} and \texttt{www.greeneconomytoolkit.com}
    \item \textbf{193 static assets deployed} across 44 HTML pages, 49 JavaScript modules, and 20 CSS stylesheets
    \item \textbf{Real-time Firestore database} for user authentication, funding applications, and interaction tracking
    \item \textbf{Multilingual support} with dynamic translation powered by Google Translate API
    \item \textbf{Mobile-responsive design} optimized for all device sizes
    \item \textbf{Firebase Authentication} with email verification and anonymous access for analytics
\end{itemize}

\section{Introduction}
The Green Economy Toolkit platform aggregates resources, opportunities, and educational content to accelerate the transition to a green economy. The platform targets township entrepreneurs, youth from underrepresented communities, TVET students, and development stakeholders. By centralizing funding opportunities, green skills training, and interactive tools, the platform reduces barriers to entry and accelerates business growth in green sectors.

\section{Technology Stack}
The Green Economy Toolkit is built on modern web technologies designed for scalability, performance, and accessibility.

\subsection{Frontend}
\begin{itemize}
    \item \textbf{HTML5} – Semantic markup for accessibility and SEO
    \item \textbf{CSS3} – Custom stylesheets for responsive design and visual consistency
    \item \textbf{Tailwind CSS} – Utility-first CSS framework (via CDN) for rapid styling
    \item \textbf{JavaScript (ES6+)} – Vanilla JS with no heavy framework dependencies, enabling lightweight modules
    \item \textbf{Font Awesome 5.15} – Icon library for consistent UI elements
    \item \textbf{Google Translate API} – Unofficial endpoint for multilingual page translation
\end{itemize}

\subsection{Backend \& Services}
\begin{itemize}
    \item \textbf{Firebase Realtime Database} – User authentication, email verification, and session management
    \item \textbf{Firestore} – Document-based NoSQL database for:
    \begin{itemize}
        \item User profiles and questionnaire responses
        \item Funding opportunities and applications
        \item Event and news content
        \item Interaction tracking and analytics
        \item Admin configurations and password management
    \end{itemize}
    \item \textbf{Firebase Authentication} – Email/password sign-in, anonymous auth, and email verification
    \item \textbf{Firebase Hosting} – Static asset delivery and SSL/TLS termination
\end{itemize}

\subsection{Deployment \& DevOps}
\begin{itemize}
    \item \textbf{Vercel} – Production deployment platform with automatic builds on git push
    \item \textbf{GitHub} – Version control and CI/CD integration
    \item \textbf{Custom Domains} – \texttt{greeneconomytoolkit.com}, \texttt{www.greeneconomytoolkit.com}
    \item \textbf{Node.js \& Express.js} – Local development server (optional for testing)
    \item \textbf{Python} – Translation automation script (\texttt{Trans.py})
\end{itemize}

\subsection{Analytics \& Monitoring}
\begin{itemize}
    \item \textbf{Google Analytics 4} – User behavior tracking and traffic insights
    \item \textbf{Firestore Security Rules} – Role-based access control (admins vs. public users)
    \item \textbf{Interaction Tracking} – Custom events logged to Firestore for behavioral analysis
\end{itemize}

\section{Database Architecture}
The platform uses Firestore (NoSQL) with security rules enforcing role-based access control.

\subsection{Key Collections}
\begin{itemize}
    \item \textbf{users} – User profiles (email, preferences, questionnaire responses)
    \item \textbf{admins} – Admin role assignments and permissions
    \item \textbf{admin\_config} – Platform configuration (password hash, settings)
    \item \textbf{funding} – Funding opportunities with filters (sector, type, ticket size)
    \item \textbf{opportunities} – Green economy business opportunities
    \item \textbf{events} – News and event listings
    \item \textbf{questionnaire\_responses} – User profiling data for personalization
    \item \textbf{interactions} – User behavior tracking (search, clicks, page views)
    \item \textbf{email\_verifications} – Email verification status tracking
    \item \textbf{verification\_codes} – OTP/code management for admin access
    \item \textbf{translations} – Multilingual content variants
    \item \textbf{translation\_metadata} – Translation job logs and progress
\end{itemize}

\subsection{Security Rules Highlights}
\begin{itemize}
    \item \textbf{Public Read} – Funding, opportunities, events, translations readable by all
    \item \textbf{Authenticated Users} – Can read own profiles and submit applications
    \item \textbf{Admin Only} – Database, analytics, translation manager accessible to admins only
    \item \textbf{Interactions Write} – Anonymous users can write analytics events without authentication
\end{itemize}

\section{Risk and Mitigation Plan}
% Risk Mitigation Summary

\subsection{CSS Path Resolution on Vercel}
\textbf{Risk:} Folder names with spaces (\texttt{Master Page(Header and Footer)}) break on Vercel's strict path resolution.
\textbf{Mitigation:} URL-encoded all paths to use \texttt{\%20} instead of spaces. Tested on production.

\subsection{Firebase Module Import Conflicts}
\textbf{Risk:} Non-module Firebase script tags conflict with ESM imports, causing parse errors.
\textbf{Mitigation:} Removed all non-module Firebase tags; now uses pure ESM imports via\texttt{<script type="module">}.

\subsection{Sign In/Sign Up Styling Issues}
\textbf{Risk:} Inline CSS blocks override external stylesheets, breaking color scheme.
\textbf{Mitigation:} Removed conflicting style blocks; external CSS now has full control.

\subsection{Authentication Flow}
\textbf{Risk:} Anonymous auth not available when reading protected Firestore docs.
\textbf{Mitigation:} Added auth readiness checks and retry logic before Firestore reads.
